# Сервис для управления мероприятиями

Учебный проект: REST API для создания, просмотра, обновления и удаления событий, а также бронирования мест на них.
Приложение разработано на ASP.NET Core Web API, данные хранятся в памяти во время работы приложения.
Во втором спринте добавлены: глобальная обработка ошибок через middleware, фильтрация и пагинация событий, юнит-тесты.
В третьем спринте добавлены: бронирование событий и фоновая обработка броней.

## Технологии

- C# и .NET 10
- ASP.NET Core Web API
- Dependency Injection
- Swagger / OpenAPI
- Data Annotations и автоматическая валидация моделей
- Problem Details для единого формата ошибок
- Middleware для глобальной обработки исключений
- BackgroundService для фоновой обработки бронирований
- xUnit для юнит-тестов

## Запуск проекта

Для запуска необходим [.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0) или более поздняя совместимая версия.

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/vvvotodefff/practicum_sprint_1_project.git
   cd practicum_sprint_1_project
   ```

2. Восстановите зависимости и соберите проект:

   ```bash
   dotnet restore
   dotnet build
   ```

3. Запустите приложение:

   ```bash
   dotnet run
   ```

После запуска API по умолчанию доступно по адресам:

- `http://localhost:5259`
- `https://localhost:7167`

Swagger UI доступен по адресу `http://localhost:5259/swagger`.

## API

| Метод | Маршрут | Описание | Успешный ответ |
|---|---|---|---|
| `GET` | `/events` | Получить события с фильтрацией и пагинацией | `200 OK` |
| `GET` | `/events/{id}` | Получить событие по идентификатору | `200 OK` |
| `POST` | `/events` | Создать событие | `201 Created` |
| `PUT` | `/events/{id}` | Полностью обновить событие | `204 No Content` |
| `DELETE` | `/events/{id}` | Удалить событие | `204 No Content` |
| `POST` | `/events/{id}/book` | Создать бронь на событие | `202 Accepted` |
| `GET` | `/bookings/{id}` | Получить текущее состояние брони | `200 OK` |

Для отсутствующего события операции `GET`, `PUT` и `DELETE` возвращают `404 Not Found` в формате Problem Details.

### Фильтрация и пагинация `GET /events`

Все параметры передаются в строке запроса и являются необязательными. Фильтры работают совместно (логическое И).

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `title` | string | — | Поиск по названию: без учёта регистра, частичное совпадение |
| `from` | DateTime | — | События, которые начинаются не раньше указанной даты |
| `to` | DateTime | — | События, которые заканчиваются не позже указанной даты |
| `page` | int | `1` | Номер страницы, начиная с 1 |
| `pageSize` | int | `10` | Количество элементов на странице |

Пример запроса:

```
GET /events?title=встреча&from=2026-07-01T00:00:00&to=2026-07-31T23:59:59&page=1&pageSize=10
```

Ответ возвращается в виде страницы результатов:

```json
{
  "totalCount": 12,
  "page": 1,
  "pageSize": 10,
  "items": [ /* события текущей страницы */ ]
}
```

`totalCount` — общее количество событий, подходящих под фильтры (до разбиения на страницы).

## Бронирование событий

### Модель `Booking`

| Поле | Тип | Описание |
|---|---|---|
| `id` | Guid | Уникальный идентификатор брони, присваивается сервером |
| `eventId` | Guid | Идентификатор события, к которому относится бронь |
| `status` | BookingStatus | Текущий статус брони |
| `createdAt` | DateTime | Время создания брони |
| `processedAt` | DateTime? | Время обработки брони. Пока бронь не обработана — `null` |

### Статусы брони

| Статус | Описание |
|---|---|
| `Pending` | Бронь создана и ожидает обработки |
| `Confirmed` | Бронь подтверждена |
| `Rejected` | Бронь отклонена |

В JSON статус передаётся строкой, например `"status": "Pending"`.

### `POST /events/{id}/book`

Создаёт бронь для указанного события. Обработка выполняется асинхронно, поэтому эндпоинт сразу
возвращает `202 Accepted` и не ждёт результата. Ссылка на созданную бронь возвращается в заголовке `Location`:

```
Location: http://localhost:5259/bookings/0062f294-f29b-4241-8c7c-0ac0e1f566ba
```

Тело ответа:

```json
{
  "id": "0062f294-f29b-4241-8c7c-0ac0e1f566ba",
  "eventId": "eb99a16f-ab16-464e-bf3b-b72d1967709e",
  "status": "Pending",
  "createdAt": "2026-08-11T10:45:42.0499777Z",
  "processedAt": null
}
```

Если события с указанным идентификатором не существует, возвращается `404 Not Found` в формате Problem Details.

### `GET /bookings/{id}`

Возвращает текущее состояние брони: `200 OK` с телом того же вида, что и выше.
Если брони с указанным идентификатором нет — `404 Not Found`.

### Фоновая обработка бронирований

За обработку отвечает `BookingProcessingService` — фоновый сервис на базе `BackgroundService`,
зарегистрированный через `AddHostedService`. Он работает всё время, пока запущено приложение:

1. раз в секунду опрашивает хранилище и выбирает брони со статусом `Pending`;
2. для каждой такой брони выдерживает паузу в 2 секунды — имитация обращения к внешней системе;
3. переводит бронь в статус `Confirmed` и заполняет `processedAt` текущим временем;
4. записывает результат в лог через `ILogger`.

Хранилище броней используется одновременно веб-запросами и фоновым сервисом, поэтому доступ
к внутреннему списку защищён блокировкой.

### Пример сценария использования

1. Создать событие:

   ```bash
   curl -X POST http://localhost:5259/events \
     -H "Content-Type: application/json" \
     -d '{"title":"Концерт","startAt":"2026-09-01T19:00:00","endAt":"2026-09-01T22:00:00"}'
   ```

   В ответе — `201 Created` и событие с присвоенным `id`.

2. Забронировать место на событии (подставьте `id` из первого шага):

   ```bash
   curl -i -X POST http://localhost:5259/events/{eventId}/book
   ```

   В ответе — `202 Accepted`, заголовок `Location` и бронь со статусом `Pending`.

3. Сразу запросить состояние брони:

   ```bash
   curl http://localhost:5259/bookings/{bookingId}
   ```

   Статус ещё `Pending`, `processedAt` равен `null`.

4. Подождать несколько секунд и повторить запрос из шага 3 — статус изменится на `Confirmed`,
   а в `processedAt` появится время обработки.

## Формат ответа при ошибках

Все ошибки возвращаются в едином формате [Problem Details (RFC 7807)](https://datatracker.ietf.org/doc/html/rfc7807).
Необработанные исключения перехватываются глобальным middleware `ExceptionHandlingMiddleware`, ошибки логируются через `ILogger`.

| Статус | Когда возникает |
|---|---|
| `400 Bad Request` | Ошибки валидации: некорректное тело запроса, неверные параметры пагинации |
| `404 Not Found` | Событие или бронь с указанным идентификатором не найдены |
| `500 Internal Server Error` | Непредвиденная ошибка сервера |

Пример ответа при ошибке `404`:

```json
{
  "title": "Ресурс не найден",
  "status": 404,
  "detail": "Событие с идентификатором '11111111-1111-1111-1111-111111111111' не найдено."
}
```

При ошибках валидации (`400`) дополнительно возвращается объект `errors` со списком проблемных полей.

### Пример события

```json
{
  "title": "Встреча команды",
  "description": "Пиво в честь окончания первого спринта",
  "startAt": "2026-06-22T12:00:00",
  "endAt": "2026-06-22T13:00:00"
}
```

Идентификатор `id` создаётся сервером автоматически при выполнении `POST /events`.

## Валидация

Для создания и обновления события действуют следующие правила:

- `title` — обязательное поле;
- `startAt` — обязательное поле;
- `endAt` — обязательное поле;
- `endAt` должно быть позже `startAt`.

При нарушении правил API автоматически возвращает `400 Bad Request` с описанием ошибок в формате Validation Problem Details.

## Тесты

Юнит-тесты написаны на xUnit и находятся в проекте `ProjectWork.Tests`.
Они покрывают CRUD-операции, фильтрацию, пагинацию, валидацию модели события,
а также создание броней, смену их статуса и неуспешные сценарии бронирования.

Запуск всех тестов из корня репозитория:

```bash
dotnet test
```

## Структура проекта

```text
Controllers/        — REST-контроллеры и обработка HTTP-запросов
Exceptions/         — собственные типы исключений
Middleware/         — глобальная обработка исключений
Models/             — модели данных и правила валидации
Services/           — бизнес-логика, хранилища и фоновая обработка бронирований
ProjectWork.Tests/  — юнит-тесты (xUnit)
Program.cs          — регистрация зависимостей и настройка приложения
```

## Особенности хранения данных

События и брони хранятся в коллекциях `List<Event>` и `List<Booking>` в памяти приложения.
После остановки или перезапуска приложения созданные данные удаляются.
